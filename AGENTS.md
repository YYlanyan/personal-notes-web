# Agent guidance for this repository

## README purpose

Treat `README.md` primarily as a user-facing introduction to this project. Use it to explain what Notes is, who it is for, its main features, how to install and use it, and how to configure optional integrations. Keep the writing clear and practical for someone discovering the project on GitHub.

Do not turn the README into an internal implementation diary, agent handoff, exhaustive API reference, or changelog. Put architecture and maintenance details in `docs/ARCHITECTURE.md` or other focused developer documentation, and link to those documents from the README when useful.

When changing the README, verify statements against the current application behavior and configuration. Keep install commands and environment-variable defaults accurate. Never include private notes, personal attachments, credentials, API tokens, machine-specific paths, or local `.local/` data. Preserve the project's user-facing overview when editing unrelated code.
