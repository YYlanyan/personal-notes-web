# Notes：本地 Markdown 笔记工作台

Notes 是一个运行在自己电脑上的 Markdown 笔记应用。它把笔记保存为普通 Markdown 文件，界面在浏览器中打开，适合希望自己掌握笔记文件、同时需要快速编辑和整理的人。

应用默认只监听本机地址 `127.0.0.1`，不需要账号，也不会自动把私人笔记上传到云端。笔记和附件保存在应用仓库之外；更新应用源码不会覆盖你的数据。

## 功能一览

- **Markdown 编辑**：编辑、阅读或并排查看笔记；支持标题、列表、任务清单、引用、代码块、表格、公式和图片。
- **自动保存与本机历史**：编辑内容自动保存为 Markdown，并在本地保留历史版本。
- **文件夹与搜索**：创建和整理笔记文件夹，搜索笔记标题和内容，使用标签筛选和归类。
- **笔记双链**：用 `[[笔记名称]]` 链接其他笔记；侧栏可查看反向链接和本文提到的笔记。
- **可恢复回收站**：删除的笔记和文件夹可以从回收站恢复；附件是共享文件，不会因删除笔记而被清理。
- **Markdown 数据库**：创建表格视图，添加文本、状态、数字、日期、勾选和链接字段，可筛选、排序和新增记录。数据仍以 Markdown 表格保存。
- **图片工作台**：图片可备份到本机并上传到 Cloudflare ImgBed；可浏览和搜索服务器图片，并复制 Markdown、URL、HTML 或 BBCode。
- **多个工作区**：支持私人笔记、公开笔记和可选的 Hugo 博客工作区；公开笔记和博客发布前可检查将提交的文件。
- **可选 GitHub 同步或发布**：私人工作区可使用已有 Git 远端同步；公开笔记和博客分别使用各自的发布流程。GitHub 操作由用户在界面中发起。

## 安装和启动

### 环境要求

- Node.js 20 或更新版本（包含 npm）
- Git：仅在使用 GitHub 同步或发布时需要

### 从 GitHub 安装

```sh
git clone https://github.com/YYlanyan/personal-notes-web.git
cd personal-notes-web
npm --prefix app install
npm run build
npm start
```

启动成功后，在浏览器打开 <http://127.0.0.1:4317/>。停止服务时，在运行 Notes 的终端按 `Ctrl+C`。

也可以开发模式启动，修改前端源码后页面会由 Vite 提供：

```sh
npm run dev
```

## 第一次使用

1. 启动应用并在浏览器打开本地地址。
2. 从左侧选择“私人笔记”工作区，新建笔记或文件夹。
3. 在笔记中直接输入 Markdown；编辑会自动保存。
4. 使用顶部按钮切换阅读、编辑或并排模式。左侧搜索框可搜索笔记标题和正文，也可以使用 `⌘ K` 聚焦搜索。
5. 删除的内容会进入左下角的回收站，可从那里恢复。

笔记以 `.md` 文件形式保存在数据目录的 `notes/` 下，附件备份保存在 `assets/` 下。默认数据目录为 `~/NotesData`。可用 `NOTES_DATA_ROOT` 把数据放到其他磁盘或目录；应用源码和用户数据可以分开放置。

## 图片上传配置（可选）

图片上传需要一个兼容 Cloudflare ImgBed 的服务和对应 API Token：

1. 在左侧打开“图片上传”。
2. 填写 ImgBed **服务地址**和 **API Token**；可选填写服务器文件夹，例如 `images/notes`。
3. 点击“保存配置”，之后即可选择图片上传。支持 PNG、JPG、WebP 和 GIF，单张最大 10 MB。
4. 选择返回格式后，复制上传结果，或在“服务器图片”中搜索已有图片并复制链接。

Token 由本机服务端保存于 `<数据目录>/.local/imgbed.json`，不会写入网页代码。上传时应用会在本机保存图片备份，并把图片发送到你配置的 ImgBed 服务。请只填写你信任的服务地址和 Token。

## GitHub 同步和公开发布（可选）

Notes 不会默认同步或发布私人笔记。

- **私人笔记同步**：如果数据目录已经关联 Git 仓库并设置远端，可从私人笔记工作区点击“同步”。同步前会保存当前笔记，并将变更提交、推送到该远端。请先确认该远端是你希望使用的仓库。
- **公开笔记发布**：公开笔记保存在本机的独立工作区。要启用发布，在启动应用前设置 `NOTES_PUBLIC_REPOSITORY` 为你自己的 Git 仓库地址，例如 `git@github.com:your-name/your-notes.git`。创建或连接空仓库后，应用会在确认前显示发布文件清单。公开仓库中的内容任何人都可以读取。
- **Hugo 博客工作区**：如需在应用中编辑和发布 Hugo 博客，可设置 `NOTES_BLOG_ROOT` 指向本机 Hugo 仓库。应用使用该仓库的 `content/` 目录，并在发布前显示改动清单。

公开笔记、私人笔记、博客内容和图片附件属于不同工作区。发布前请逐项检查清单，确保公开工作区不含私人资料、凭据或不打算公开的附件。

## 配置项

这些环境变量都是可选的。macOS / Linux 下可在启动前设置，例如：

```sh
NOTES_DATA_ROOT="$HOME/Documents/NotesData" PORT=4321 npm start
```

| 环境变量 | 用途 | 默认值 |
| --- | --- | --- |
| `NOTES_DATA_ROOT` | 笔记、附件和本机状态数据的根目录 | `~/NotesData`（独立安装） |
| `PORT` | 本地服务端口 | `4317` |
| `NOTES_PUBLIC_REPOSITORY` | 公开笔记工作区的发布目标；设为空字符串时关闭发布 | 未设置时关闭（独立安装） |
| `NOTES_BLOG_ROOT` | 本机 Hugo 博客仓库路径 | 不启用博客工作区 |
| `NOTES_ROOT` | 私人笔记工作区根路径，通常无需手动设置 | 独立安装时与数据目录相同 |

服务仅绑定 `127.0.0.1`。不要通过公网反向代理暴露此服务；应用不提供面向公网的用户认证。

## 数据与备份

Notes 使用文件系统保存数据，不需要数据库。请定期备份数据目录，特别是 `notes/`、`assets/` 和 `.local/`。`.local/` 包含 ImgBed 配置、回收站、历史记录和发布状态等本机数据；不要将它提交到公开仓库。删除笔记不会自动删除共享附件。

## 项目结构

- `app/`：网页界面、本地服务端和应用源码
- `notes/`：随公开项目提供的示例笔记内容
- `assets/`：公开笔记使用的示例附件
- `examples/`：可复制参考的示例文件
- `start.mjs`：启动入口
- `docs/ARCHITECTURE.md`：开发者参考的架构和数据边界说明
- `app/dist/`：由 `npm run build` 生成的网页资源

问题反馈或功能建议请使用 GitHub Issues。欢迎改进项目；提交前请确认没有包含个人笔记、附件、Token 或其他私人数据。
